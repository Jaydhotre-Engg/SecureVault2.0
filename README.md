SecureVault 2.0 uses the Ethereum Sepolia Testnet to create an immutable
external proof of digital evidence integrity.

- Evidence ID
- Original SHA-256 evidence hash
- IPFS CID
- Chain of Custody hash
- Blockchain timestamp
- Anchoring wallet address

This allows the system to independently compare its current evidence
metadata against an immutable blockchain record.

Blockchain Design Principles

SecureVault follows these principles:

1. Blockchain stores proof, not evidence

The actual evidence remains encrypted and stored through IPFS.

2. Sensitive information stays off-chain

Passwords, private keys, JWTs, and encryption keys are never stored on
Ethereum.

3. Hashes provide integrity verification

The SHA-256 digest allows the system to detect changes to evidence.

4. IPFS provides decentralized artifact storage

The blockchain stores the IPFS CID as a reference to the encrypted
artifact.

5. Chain of Custody provides lifecycle integrity

The custody hash represents the evidence's custody history.

6. Blockchain provides an immutable external anchor

The Ethereum record allows SecureVault to independently verify that the
anchored proof has not been modified.

7. Verification is read-only

Blockchain verification does not require a wallet or blockchain
transaction from the user.
